# Mantis appearance and elemental blade effects — 0.16.1

The 0.16.0 variants added hardware but retained very similar receivers. This update reshapes the receiver cross sections and makes their mechanical details more visible without changing the accepted arm framing, hinge pivots or animation timing.

| Variant | Appearance | Local effect | Near / far triangles per arm |
| --- | --- | --- | ---: |
| Physical | Original steel receiver | None | 3,504 / 588 |
| Thermal | Broader dark receiver, swept copper radiator vanes, ceramic shielding | Low-opacity heat wisps and a warm edge glow | 3,756 / 744 |
| Electrifying | Narrow silver receiver, forked electrodes, insulated rails and coils | Thin crawling cyan filaments | 4,064 / 928 |
| Toxic | Olive receiver, enlarged reservoirs, swept injector barbs | A narrow green glow and drifting vapor | 3,956 / 980 |

All three also have different original pixel-art inventory silhouettes. The receiver meshes are generated by Blender, with normals corrected after changing the cross sections. Hardware `.blend` files retain editable additions; the base receiver deformation is specified in `art/mantis/build_variants.py`. Runtime exports contain both the modified base and the additions. The existing 0.16.0 research references and Minecraft combat adaptations still apply.

## Effects and cost

The original 64×32 soft texture is shared across three deterministic effect patterns. Ribbons follow the actual articulated blade, tip and edge matrices, so extending, retracting and attacking keep the effect attached. The emitter time includes per-player and per-hand offsets. Filament motion interpolates continuously rather than replacing the whole blade's glow every tick. Render opacity fades in over the final part of deployment.

The effect uses one cached emissive render type and a reused 16 KiB buffer, with maximum **54 Thermal, 66 Electrifying or 42 Toxic quads per arm**. Effects fade over 10–16 blocks and are skipped for the far LOD and Sandevistan's captured poses. This avoids multiplying vapor/arcs over every afterimage. No persistent particles, entities, dynamic lights, terrain changes, extra texture uploads or file reads are created during rendering. It is a small emissive overlay, not a screen-wide bloom/post-processing pass.

## Verification

The moving-cover intersection test covers every variant near/far mesh, the full deployment path at half-tick intervals, and both regular/slim arm depths. Early expanded fins intersected the proximal cover while folded; their shapes were adjusted within the stowed envelope before the final check. The mesh budgets remain below the existing 4,200 near / 1,000 far triangle limits.

The native review deploys, attacks and retracts all four types, checks six-group synchronization, asserts that Physical has no elemental ribbons and the other types have a bounded nonzero quad count, and captures daylight, night and third-person views. It also repeats the item-model/translation gallery and bow preview. Rendering uses the disposable integrated world and software OpenGL; it is not a hardware benchmark or a two-computer test. No working audio device or session-service connection was available. Dedicated-server combat tests are not rerun for this client/art-only change; the previous gameplay release passed 112.
